## Project

**Novo** — a configurable theme for Dolibarr ERP v21+, shipped as two
artifacts with zero core edits: the `novo` skin (CSS generated by PHP, plus
one vanilla-ES2020 JS file) and `novoux`, a companion Interface-family module
that provides the admin GUI, per-user preferences and CSS injection. Eight
colour palettes and three density levels are generated from JSON design
tokens; every rule uses `--novo-*` custom properties, so a rebrand is one CSS
file. English and French translations ship with it.

**This repository is public and GPL-3.0** — the only public repo in its group.
It is distributed to third parties through DoliStore and GitHub Releases as
`module_novoux-VERSION.zip`, and support is explicitly community, best-effort,
with no response-time commitment. The GitHub Pages preview at
`flowmatrix-ai.github.io/dolibarr-novo-theme` is also public.
[`docs/architecture.md`](docs/architecture.md) is the design reference.

## Commands

```bash
docker compose -f docker-compose.dev.yml up -d   # Dolibarr on :8080; the admin
                                                 # login defaults are in the compose file
node scripts/build-palettes.js                   # regenerate palettes/ + variants/
bash scripts/check-version.sh [vX.Y.Z]           # version strings agree
bash scripts/package.sh                          # build the distribution zip
bash scripts/seed-dev.sh                         # seed data + activate the module
npm ci
npm run test:smoke                               # Playwright, needs the stack up
npm run test:visual                              # Playwright visual snapshots
npm run test:visual:update                       # re-baseline those snapshots
find dolibarr/ -name '*.php' -print0 | xargs -0 -n1 php -l
node --check dolibarr/custom/novoux/theme/novo/novo.js
```

There is no `justfile`. CI (`ci.yml`) is three jobs behind `ok`:

| Job | What it proves |
| --- | --- |
| `validate` | version strings agree, release-tracker fixtures, PHP lint, JS syntax, the distribution zip's shape, and that `palettes/` + `variants/` are freshly generated (`git diff --exit-code`) |
| `phpunit` | installs Dolibarr `develop` against MariaDB and runs `test/phpunit/` |
| `smoke` | boots `dolibarr/dolibarr:{21.0.0,22,23,24}`, activates the module in both install roots, runs the Playwright smoke suite, and **fails on any PHP warning in the server log** |

## Architecture

```text
dolibarr/custom/novoux/
  core/modules/modNovoux.class.php   module descriptor (id 194081, family interface)
  admin/                             setup + about pages
  class/actions_novoux.class.php     hooks
  css/novo-inject.css.php            injected CSS for runtime overrides (colour, logo)
  lib/, langs/en_US, langs/fr_FR, sql/data.sql
  user_prefs.php                     per-user palette/density/colour overrides
  theme/novo/
    style.css.php                    entry point; emits Content-Type: text/css
    theme_vars.inc.php               PHP colour vars
    global.inc.php                   :root tokens, dark mode, component CSS
    *.inc.php                        badges, btn, dropdown, info-box, progress, timeline
    novo.js                          sticky headers + dark-mode toggle (ALLOW_THEME_JS)
    palettes/*.css  variants/*.css   GENERATED — do not edit
    theme_descriptor.php             carries $theme_version
tokens/*.json  tokens/variants/*.json   the generated files' source
preview/                             the Vite app published to GitHub Pages
tests/smoke/  tests/visual/          Playwright suites
scripts/                             build, package, version, seed, release-tracking
docs/                                architecture, developing, docker, research
```

`style.css.php` requires Dolibarr's `main.inc.php`, resolved via
`CONTEXT_DOCUMENT_ROOT` with fallbacks, because the module must work from both
`htdocs/custom/novoux/` and `htdocs/novoux/`.

Four workflows:

| Workflow | Trigger | Effect |
| --- | --- | --- |
| `ci.yml` | push to `main`, PR | the three jobs above |
| `release.yml` | tag `v*` | checks the tag against the version strings, rebuilds palettes, packages, publishes a GitHub Release with the zip |
| `pages.yml` | push to `main` touching `preview/**` or `tokens/**` | deploys the public preview |
| `dolibarr-releases.yml` | Mondays 13:17 UTC | opens a tracking issue per Dolibarr release newer than the declared max, escalating majors against DoliStore's 8-month update rule |

## What NOT to do

- **Do not write anything here you would not publish.** The repo, its issues
  and the Pages preview are public. Do not name a private FlowMatrix repo,
  link one, or describe internal structure in code, comments, commit messages,
  issues or release notes. Contributions come from outside the org.
- **Do not add code under an incompatible licence.** The distribution is
  GPL-3.0 and ships to third parties through DoliStore.
- **Do not edit `theme/novo/palettes/*.css` or `theme/novo/variants/*.css`.**
  They are generated from `tokens/` by `scripts/build-palettes.js`, and CI
  rebuilds them and fails on `git diff --exit-code`. Edit the tokens, then
  regenerate and commit both.
- **Do not bump one version string.** `scripts/check-version.sh` requires
  `package.json`, `package-lock.json`, `modNovoux.class.php` and
  `theme_descriptor.php` to agree, and on a release also requires the tag to
  match. These drifted before — `theme_descriptor` sat at 1.1.0 through three
  releases — and a mismatch at release time publishes a Release with no zip.
- **Do not trust `php -l` as proof the theme loads.** Linting never *executes*
  `style.css.php`, which is how a broken `main.inc.php` include shipped (#12).
  The `smoke` job booting a real Dolibarr is the check that catches it.
- **Do not assert on the HTTP response body to detect PHP errors.**
  `display_errors` is off in the Dolibarr image, so diagnostics never reach
  the body. The server log is the only place they surface — which is why #43
  (12 partials silently failing to include on every request) was invisible to
  the suite. The log grep in `smoke` is load-bearing; do not weaken it.
- **Do not assume one install root.** The module has to work from
  `htdocs/custom/novoux/` *and* `htdocs/novoux/`; compose only provides the
  first, so CI copies it into the second and runs the smoke suite with
  `TEST_SECOND_ROOT=1`.
- **Do not let dev-only files into the zip.** CI asserts the zip contains the
  module descriptor, `style.css.php`, the `en_US` lang file, `docs/LICENSE`
  (and that the licence is the real text, not a truncated placeholder) and
  `docs/INSTALL.md` — and that it does **not** contain `novoux/test/` or
  `.gitkeep`.
- **Do not edit Dolibarr core, and do not fork per client.** Both are standing
  constraints: zero core edits is what makes the theme survive Dolibarr
  upgrades, and per-client variation goes through `--novo-*` overrides or
  `llx_const`, never a fork.
- **Do not add a runtime dependency.** No Composer, no npm at runtime — the
  theme and module must install from a zip. npm here is dev-only (Playwright,
  the preview build).
- **Do not widen the compatibility range in `modNovoux.class.php` without the
  matrix.** Both ends of the declared range are exercised by the `smoke`
  matrix precisely so the claim on DoliStore cannot quietly become false; add
  the version to the matrix in the same change.
